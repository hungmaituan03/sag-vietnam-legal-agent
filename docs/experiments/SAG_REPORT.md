# SAG on the finance corpus — what was built and what it does

Status report for the SAG stage of the pipeline. Every number here comes from a
live run against the approved corpus (`data/raw/uts_vlc_processed.json`,
finance pack) with the real Voyage reranker. Nothing is synthetic.

## 1. Where SAG sits

```text
ingest/chunk → BM25 → dense → hybrid (RRF) → Voyage rerank → SAG → (LLM) → (Hindsight)
```

SAG runs **after** the reranker and **expands** its shortlist. It does not rank
anything and never replaces a retrieved chunk.

That division matters. Retrieval is good at finding the most relevant *fragment*
and bad at anything else, because chunking split the law into pieces that are
not self-contained. A điểm is a grammatical continuation of its khoản; on its
own it is unanswerable.

Real example, Voyage rank 4 for `kỳ kế toán năm` at score 0.7656:

```
Điều 40, Khoản 2, Điểm a | a) Cuối kỳ kế toán năm;
```

Five words. End of the accounting year — and *what*? After SAG expansion the
model also sees the heading `Điều 40. Kiểm kê tài sản`, the stem
`2. Đơn vị kế toán phải kiểm kê tài sản trong các trường hợp sau đây:`, and the
five sibling triggers b–e. Only then is the fragment a rule.

## 2. The data model

Every chunk is an **event**. **Entities** are the things events share.

| Entity kind | Example | Count (finance pack) |
| --- | --- | --- |
| `law::` | `law::luat-ke-toan` | 5 |
| `art::` | `art::luat-ke-toan::Điều 12` | 551 |
| `cls::` | `cls::luat-ke-toan::Điều 12::Khoản 1` | 2056 |

Keys carry the `document_id`, so `Khoản 1` of one article never merges with
`Khoản 1` of another: 480 distinct entities in this corpus end in `Khoản 1`, all
separate.

The index is two maps plus a graph:

```text
events_by_id      chunk_id -> LegalChunk          (the events table)
events_by_entity  entity   -> [chunk_id, ...]     (the join table)
neighbours        chunk_id -> [(chunk_id, cos)]   (the similarity graph)
```

`events_by_entity` stores ids, not chunks. Looking up an entity and getting back
its event ids is the in-memory equivalent of the SQL join the full SAG design
does at query time.

## 3. Two edge types

**Structural** — events sharing a Điều. Free, exact, always correct, but they
can never leave the document they came from.

**Semantic** — cosine k-NN over the cached corpus embeddings, built once at
index time. These are the edges that cross laws.

On the finance pack: 4094 events, 2612 entities, ~19.4K semantic edges built in
0.2s from cache. Roughly 23% of semantic edges connect different laws.

## 4. Query-time expansion

`expand(seeds, index, max_extra, hops, min_sim)` is a bounded breadth-first walk
from the reranked seeds. Three properties are load-bearing:

- **Seeds stay in front.** Voyage already ranked them; expansion is additive.
- **Added chunks carry no score.** They return as plain `LegalChunk`, not
  `ScoreChunk`, because they were never scored against the query. Inventing a
  score would mislead every stage downstream.
- **The budget is shared round-robin** across the frontier, and each seed's
  candidates are ordered by kinship — heading, then the seed's own khoản, then
  điểm siblings, then the rest of the article.

## 5. Results

Six queries, live Voyage, defaults (`hybrid-k=20`, `voyage-k=5`,
`sag-extra=30`, `min-sim=0.7`, `max-sim=0.99`). Generated by
`scripts/run_sag_evidence.py`; full table in `sag_evidence.md`.

*Orphan* = a reranked seed that is a fragment whose parent text was missing from
the shortlist. *New law* = a statute no seed came from.

| Metric | Result |
| --- | --- |
| Orphaned fragments repaired | **23 / 23** |
| Queries reaching a law no seed came from | 2 / 6 |
| Context size | 5 seeds → 31–35 chunks |
| End-to-end latency, one query | ~17s (cached embeddings) |

Orphan repair is what the Voyage shortlist structurally cannot do for itself.
Cross-law reach is the part that is genuinely retrieval rather than context
repair.

## 6. Failures found by running on real data

Each of these was invisible in unit tests and only appeared against the corpus.

**Duplicate collapse.** `e) Thông qua báo cáo tài chính hằng năm;` appears
verbatim in Điều 138 and Điều 147 of Luật Doanh nghiệp. Both chunks had the
*same five neighbours*, all restatements of one sentence, so expanding either
fed the model five copies of what it already had. Fixed with `max_sim=0.99`,
masking near-duplicates **before** top-k selection so the freed slot goes to a
real neighbour: 270 duplicate edges removed, total edge count unchanged.

**Budget starvation.** With a single global budget the first seed's article
consumed everything and three of five seeds contributed nothing. Fixed by taking
candidates round-robin across the frontier.

**Unreachable parents.** Article buckets are in document order, so a seed's own
khoản can sit deep in a long Điều — position 39 of 46 in one case. The
round-robin walk only reaches the first few positions of each list, so those
parents were never read:

```
seed                        | parent          | bucket | parent position | repaired?
Điều 4, Khoản 30, Điểm a    | Điều4::Khoản30  |   46   |     pos 39      | NO
Điều 4, Khoản 29            | Điều4           |   46   |     pos  0      | YES
Điều 66, Khoản 2, Điểm b    | Điều66::Khoản2  |   16   |     pos 10      | NO
```

Fixed by ordering candidates by kinship to the seed. Repair went from 19/22 to
22/22 *and* got cheaper: that query now repairs 5/5 at `max_extra=10`, where the
old ordering managed 2/5 at 30. Ordering beat budget size.

## 7. Limitations

- **Cross-law reach is seed-dependent.** At `hybrid-k=12` three of six queries
  reached a new law; at `hybrid-k=20` only two, because a wider shortlist
  changes which seeds Voyage picks. Orphan repair is stable at 100% either way —
  the structural claim is robust, the semantic one varies.
- **Tightening `min_sim` costs cross-law reach.** Raising it from 0.6 to 0.9
  drops the cross-document share from 23% to 13%: the most similar pairs are
  overwhelmingly inside the same law, because statutes reuse their own
  boilerplate. Precision here is bought with exactly the reach SAG exists for.
- **Paraphrases still crowd lists.** `max_sim` only catches near-verbatim
  repeats. An MMR λ sweep suggests λ≈0.5 before diversity changes the ordering
  at all; λ=0.3 drifts off-topic. Not implemented.
- **Hub nodes.** One boilerplate clause appears in 31 other nodes' top-5.
- **Dense similarity matrix is O(n²).** 67MB at 4094 chunks, fine here, needs an
  approximate index beyond ~100K.
- **Short fragments embed poorly**, so some semantic links are topical rather
  than legal.
- **Duplicate chunk ids** exist in the source: all front matter is `<doc>::body`.
  The index keeps the first; the real fix belongs in the chunker.
- **Source text has missing spaces** (`kỳ kế toánnăm`), which hurts lexical
  matching.
- **No temporal filtering yet.** An expired provision can be a neighbour of an
  active one.

## 8. Deliberately not built

LLM entity extraction (Qwen), MySQL, Elasticsearch, frontier hops beyond 1–2,
LLM answer generation, Hindsight.

The storage layer is deferred on purpose: at 4094 chunks, dicts are the tables
and numpy is the vector store. The join logic is the part worth getting right,
and it is written so the storage can move later without changing the interface.

The same is true of entity extraction. `entity_keys` returns coordinates today;
adding `concept::kỳ kế toán năm` keys from an LLM pass later changes that one
function, and `build_index` and `expand` stay as they are.

## 9. Reproducing

```bash
source .venv/bin/activate
ruff check src tests && pytest -q          # 74 tests, no corpus or API key

# one query through all four stages, plus the ablation
python scripts/run_finance_retrieval.py --query "kỳ kế toán năm"
python scripts/run_finance_retrieval.py --query "kỳ kế toán năm" --no-sag

# the six-query measurement that produced sag_evidence.md
python scripts/run_sag_evidence.py
```

Voyage's free tier allows 3 requests and 10K tokens per minute, counted as
`query_tokens × n_documents + sum(document tokens)`. The evidence script paces
itself and retries with backoff, so six queries take about three minutes. That
is a billing-tier constraint, not a property of the system.

## 10. Next steps

1. Ancestor-first ordering exists for structural edges; apply the same idea to
   semantic ones (prefer cross-document neighbours, since same-law neighbours
   are often redundant with the structural edge).
2. MMR-style diverse selection, tuned against the six-query harness.
3. Temporal filtering: never expand into a provision that was not in force.
4. Instruction-following in the Voyage call to push definition articles down.
5. Concept entities from an LLM pass — the first edges that are neither
   structural nor embedding-based.
